# B02 排名适配器书面合同（A1 首单例外第 ① 项）

适配器名（拟议）：`ranking-public-adapter`。当前状态：书面合同，未实现。实现位置待开发阶段固定（本产品目录后端补丁）。对应缺件：01-a1-check.json B02。依据：01-dev-spec.md 第 4、7 节；LI 2026-11-16 定后端自取公开数据、不接上游。

## 1. 数据源与口径

### 1.1 Google Trends（自跑）

- 方式：以 pytrends 类开源库读公开 Trends 网站。
- 费用：许可费 0，无 key，无单次费用（来源：GitHub GeneralMills/pytrends 公开页，2026-10 核验记录；Apache 2.0）。
- 重要限制：该库 2025-04-17 已由作者归档只读，最新版 4.9.2（2023-04），无维护；Google 改前端即可能中断，须退避重试。Google 官方 Trends API 仍为邀请制 alpha，不可用。
- 只出 `interest_score`（0–100 相对兴趣），永不进名次表、不推断排名升降、不混为一列。

### 1.2 亚马逊公开搜索结果页（免登录抓取）

- 只出 `rank_ordinal`（页面上可核的正整数名次）；`page_index` 仅来源显式给出时填；`page_size` 永不设平台常数（不默认 10/48）。
- 无登录 Cookie，不接卖家后台，不抓需登录私有数据，不代刷排名，不承诺回升。

### 1.3 user_records

- 只处理用户粘贴记录，不接供应商；仍走服务端计费，客户端不得自报扣费成功。

## 2. 有效单位（LI 2026-11-16 定）

一个有效单位 = 原任务去重后、来源可核、口径有效的一行观测（`rank_ordinal` 正整数，或已登记合同的其他 metric 有效值）。`missing` / `not_found` / `capped` / `ambiguous` / `invalid` 行不收费；一条有效结果都没有不收费；零结果、档案缺失、上游失败、字段映射失败、额度保护五类逐项 0 费。同一观测 key 的完全相同记录去重，重复行不增加有效单位。

## 3. 部分结算与预算

仅按实际有效单位结算，其余保留缺项与原因；任务预算上限；收费前两次确认；quote 版本/有效期；报价/范围增加或过期后尚未提交的收费动作重新复述并明确同意。

## 4. 幂等

`operation_key` 绑定 skill＋账户＋原 task＋动作＋同一参数；同 key 重放还原原结果/账单，新增费用 0；已收到上游 HTTP 200 仍须映射和有效结果/五类 0 费判定，不能立刻扣费。

## 5. 限额与失败

429 退避重试；抓取受限、额度保护、无数据、映射失败保留独立状态，不自动切换口径冒充同一序列；不把“上游 HTTP 成功”直接等同可收费。
