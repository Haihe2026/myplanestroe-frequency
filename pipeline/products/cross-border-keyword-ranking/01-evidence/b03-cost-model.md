# B03 有来源的成本模型（A1 首单例外第 ③ 项）

对应缺件：01-a1-check.json B03。依据：LI 2026-11-16 定单价 0.30 元/有效单位；SOP 毛利阈值 ≥0.6。

## 1. 价格与上限

- 单价：0.30 元/有效单位（LI 定；listing 页实测显示 0.30元/次，见 B01）。
- 毛利阈值：≥0.6。按代数，成本上限 = 0.30 × (1 − 0.6) = 0.12 元/有效单位。这只是上限算式，不是实际成本。

## 2. 成本分项（每项注明来源，不以未知记 0）

| 成本项 | 单次费用 | 来源 |
|---|---|---|
| Trends 取数（pytrends 类开源库） | 许可费 0，无 key，无单次费用 | GitHub GeneralMills/pytrends 公开页（Apache 2.0）；见 B02 第 1.1 节。成本是维护与退避时间，非按次费用 |
| 亚马逊公开页抓取 | 无单次费用 | 公开页面，无付费接口；成本为计算与带宽。封禁风险属可用性风险，非费用 |
| 计算与存储 | 已有共享服务器边际成本，未单独计量 | 同一后端已在跑生图线账单；单任务为数次 HTTP 请求加数 KB 行存储，边际成本远低于 1 分/任务（量级判断，见第 3 节） |
| Logo | 1 次上游生图调用，一次性成本 | 见 B04；不按有效单位摊 |

## 3. 毛利计算

- 最坏情况：成本取上限 0.12 元/有效单位，毛利 = (0.30 − 0.12) / 0.30 = 0.6，恰好达到阈值。
- 实际情况：采集单次费用为 0（有来源），计算存储为已有服务器边际成本（量级远低于上限），实际成本低于上限，实际毛利高于阈值。
- 本模型不把未计量写成 0：计算存储未单独计量，写的是“边际成本量级＋上限反推”，不是 0；开发阶段以部署实测复核，单有效单位分摊超过 0.12 元即拦停。

## 4. 结论

毛利阈值按最坏情况恰好达到，实际高于阈值；无月费备用；不新增供应商，不自动试调用。
